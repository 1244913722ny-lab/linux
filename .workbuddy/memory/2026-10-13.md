# 2026-10-13 LVGL 桌面启动器改造

## 目标
把 `file/app` 的 LVGL demo 从"按钮+计数器"改成**桌面启动器**：主界面是深色桌面，排列 5 个 LVGL 内置 demo 的磁贴（Widgets/Benchmark/Keypad/Music/Stress），点击磁贴加载对应 demo，右上角常驻 Home 按钮（鼠标）返回桌面。

## 改动文件
- `main.c`：重写为桌面启动器。
  - demo 注册表 `{name, symbol, color, open(), close()}`（5 个 demo 的 `*_close()` 全部可用）。
  - `build_desktop()`：深色背景 + 标题 + flex 换行网格磁贴（图标符号 + 名称），磁贴加入键盘导航 group。

  - `create_home_button()` 放在 `lv_layer_top()`（切屏不消失）。
  - 鼠标光标挂到 `lv_layer_top()`（被 `lv_indev_set_cursor` 自动 reparent 到 layer_sys）。

- `Makefile`：`SRCS` 增加 `$(shell find $(LVGL_DIR)/demos -name '*.c')`；`CFLAGS` 增加 `-I$(LVGL_DIR)/demos`（main.c 用 `#include "lv_demos.h"`）。
  - music demo 的图片是 `demos/music/assets/*.c`（`LV_IMG_DECLARE`），已被 `find` 编入，链接无问题，不依赖运行时读 png。

## Makefile 自动依赖（告别 make clean）
- 用户问"为何每次改完都得 make clean"：根因是旧 Makefile 每个 .o 仅依赖对应 .c，未把头文件/lv_conf.h/Makefile 本身列为依赖。改 lv_conf.h 或 CFLAGS 后 .c 时间戳不变 -> make 认为已最新 -> 不重编，必须 clean。
- 改进（`file/app/Makefile` 4 处）：CFLAGS 加 `-MMD -MP` 让 gcc 生成 .d；compile_rule 把 `$(MAKEFILE_LIST)` 列为依赖并收集 DEPS；foreach 后 `-include $(DEPS)`；BUILD_DIR 系列去 `./` 前缀（避免 .d 目标名带 ./ 不匹配）。
- 效果：改 .c/.h/lv_conf.h/CFLAGS/Makefile 后直接 `make` 即精确重编；仅想彻底重来才需 `make clean`。改完后**首次**建议 `make clean && make`（旧 .o 无对应 .d，需重建依赖图），之后免 clean。未实编，待用户验证。

## QEMU 启动期报错修复（can't open /dev/tty2/3/4 刷屏）
- 现象：内核启动后反复刷 `can't open /dev/tty2/3/4: No such file or directory`。
- 根因：`rootfs/build/etc/inittab` **缺失**，busybox init 套用内置默认 inittab，对 tty2/3/4/5 执行 askfirst 登录 shell；但内核 `console=ttyAMA0`（boot.cmd:11），板子无帧缓冲虚拟终端，/dev/tty2~4 节点不存在 -> 开不出来；又因 askfirst/respawn 退出后重启 -> 无限刷屏。与网络配置无关，是 rootfs 老问题（之前 QEMU 因 `-device lan9118` 解析失败起不来，内核没跑，故看不见；网卡通后暴露）。
- 修复：新建 `rootfs/build/etc/inittab`，只保留串口控制台：
  ```
  ::sysinit:/etc/init.d/rcS
  console::askfirst:-/bin/sh
  ::restart:/sbin/init
  ::ctrlaltdel:/sbin/reboot
  ```
  `console` 解析为 /dev/console（即 ttyAMA0，对应 telnet 4321 进来的 shell）。
- 生效步骤（用户侧）：`cd rootfs && sh pack.sh` 重打包 rootfs.uimg -> `mcopy -i ../uboot-start/full_sd.img@@1M rootfs.uimg ::/rootfs.uimg` -> `./start_uboot.sh`。inittab 必须进 rootfs.uimg 才生效。
- 备注：用户强调"改代码前必须先询问/确认"，本次严格先提案、待用户回"需要"后才创建文件。该规则已在长期记忆中。start_uboot.sh 的 `-device lan9118` -> `-net nic,netdev=net0` 修复提案用户尚未明确确认（但用户已能启动 QEMU，疑似自行改过或绕过）。

## 排查 eth0 NOT found（网络起来不了）
- 现象：`System initialized...` 后 `Bringing up network (eth0)...` -> `Network: eth0 NOT found (check QEMU -device lan9118).`（rcS 末尾等待 /sys/class/net/eth0 最多 10s，超时即报）。用户指认 `linux-5.0.17/arch/arm/boot/dts/vexpress-v2p-ca9.dts` 是内核 DTS。

## 根文件系统缺挂载点目录导致启动崩（用户回"改吧"已修复）
- 现象：启动日志 `mount: mounting proc on /proc failed`、`mount sysfs on /sys failed`、`can't create /proc/sys/kernel/hotplug`、`mdev: /sys/dev: No such file`、`/mnt/sdcard` 也没了。
- 根因：`rootfs/build/` 实际只有 `bin etc lib sbin usr linuxrc`，**缺 proc/sys/dev/mnt/tmp/root 这些标准目录**。`pack.sh` 是 `cd build && find . | cpio`，源缺目录 -> 打包出的 rootfs.uimg 也无这些目录 -> 板子起来后挂载点不存在、mdev 扫不了 /sys 创建设备节点 -> /dev/mmcblk0p1 无节点 -> SD 卡挂不上。此前能跑是因为旧 rootfs.uimg 由更完整的源打包。
- 修复（用户已确认"改吧"）：
  1. 在 `rootfs/build/` 补建空目录 `proc sys dev mnt mnt/sdcard tmp root`（cpio 会把空目录打进镜像）。
  2. `rcS` 开头（mount 之前）加防御性 `mkdir -p /proc /sys /dev /tmp /mnt/sdcard`，以后源目录再缺也不会因挂载失败而崩。
- 生效步骤（用户侧）：`cd rootfs && sh pack.sh` -> `mcopy -i ../uboot-start/full_sd.img@@1M rootfs.uimg ::/rootfs.uimg` -> `./start_uboot.sh`。仅此修复解决"启动崩/挂载点缺失/sdcard 挂不上"。eth0 缺失那个老问题（QEMU LAN9118+smsc911x 运行时兼容坑）仍需板子侧 `dmesg` 诊断，未动。rcS 第 85 行误导性 "check QEMU -device lan9118" 提示暂未改（待 eth0 诊断结论）。
